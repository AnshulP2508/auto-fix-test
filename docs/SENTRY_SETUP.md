## Alerts

Configure these alerts in Sentry:

1. Error Rate Alert: error rate greater than 5% in 5 minutes, notify Slack `#alerts`.
2. Payment Error Alert: any error tagged `payment.method`, notify Slack `#payments` and email the team lead, critical priority.
3. Performance Alert: p95 response time greater than 2000ms, notify Slack `#performance`.
4. New Issue Alert: first occurrence of any new issue, notify Slack `#bugs`.
5. Cron Job Alert: `order-cleanup-job` missed check-in, notify backend team email.

## Source Maps

Frontend source maps are handled by `withSentryConfig()` in `frontend/next.config.js`. Next.js 14.2 does not load `next.config.ts`, so this project keeps the runtime config in JavaScript while preserving the requested Sentry settings.

Backend source maps are generated by `backend/tsconfig.json` with `sourceMap: true` and uploaded from `.github/workflows/sentry-release.yml`.

For production:

- Use `NEXT_PUBLIC_APP_VERSION` and backend `APP_VERSION` equal to the git SHA.
- Keep `hideSourceMaps: true`.
- Do not publicly serve sourcemaps.

## PII Rules

The backend strips request bodies, cookies, authorization headers, and database credentials in `beforeSend`.

The frontend strips auth tokens from URL breadcrumbs, filters browser extension errors, filters development ChunkLoadErrors, and masks credit-card-like patterns.

## Cron Monitoring

Use this pattern for scheduled jobs:

```ts
const checkIn = Sentry.captureCheckIn({
  monitorSlug: 'order-cleanup-job',
  status: 'in_progress'
});

try {
  // job work
  Sentry.captureCheckIn({ checkInId: checkIn, monitorSlug: 'order-cleanup-job', status: 'ok' });
} catch (error) {
  Sentry.captureException(error);
  Sentry.captureCheckIn({ checkInId: checkIn, monitorSlug: 'order-cleanup-job', status: 'error' });
}
```

## Correlation IDs

The frontend sends `x-correlation-id` on all API calls. The backend echoes it in the response and attaches it to Sentry as `correlation_id`, allowing frontend and backend events for the same user action to be linked.
